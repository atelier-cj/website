# 荧的炼金工房

> Atelier Lumine · 原神 AI 配装助手
>
> **闭源产品** · 本站仅作生态展示，源码未公开。

一个本地运行的原神配装应用：管理角色库、武器与圣遗物、多套配装和配队，配装与养成问题交给 Agent 回答。游戏数据与存档都在本机，不经过第三方服务。

## 它解决什么问题

配装与配队是**知识密集型**问题：同一把武器在不同角色身上价值不同，圣遗物主副词条要看角色机制，命座与天赋等级又改变结论。现成的计算器只给面板数字，「这套够不够用」还得人自己判断。

荧的做法是把两件事分开：确定性计算（面板、词条、套装）交给代码，理解意图与组织结论交给 Agent。所以它既能查「胡桃 90 级的暴击率」，也能回答「这套配装的元素精通够不够」。

## 核心能力

| 功能 | 说明 |
|---|---|
| 帐号与存档 | 多帐号，角色数据按帐号隔离；存档在本地 |
| 角色库 | 列表 + 筛选（元素 / 武器 / 星级 / 国家 / 性别 / 体型）+ 搜索 |
| 角色详情 | 等级/命座/天赋、固有天赋、命座全文、「魔导角色」与「魔女的谕示」加强档 |
| 配装方案 | 每个角色多套方案，每套 = 武器 + 5 件圣遗物（主词条 / 副词条 / 套装） |
| 配队 | 队伍编排与查看 |
| 快速配装 | 按 2 件套效果分组的套装选择 + 5 个部位主词条 + 副词条模板，一次铺满方案 |
| 资料库 | 角色 / 武器 / 圣遗物资料检索 |
| 米游社同步 | 粘贴 Cookie 或 cURL，从米游社养成计算器拉取全部角色（等级/突破/天赋/命座/武器/圣遗物）并导入存档 |
| AI 助手 | 多会话对话；可附分享图提问、可 `@角色` `#武器` 引用；工具调用带授权确认 |
| 登录 | 打开先登录，帐号切换不丢数据 |

## 它同时是一个 MCP 服务

内核能力被注册成 11 个 MCP 工具，任何 MCP 客户端（Claude、opencode、Cherry Studio 等）都能把它当成原神资料与配装的服务端：

| 工具 | 用途 |
|---|---|
| `genshin_character` / `genshin_weapon` / `genshin_artifact` | 角色 / 武器 / 圣遗物套装的基础资料 |
| `genshin_talent` / `genshin_passive` / `genshin_constellation` | 天赋倍率、固有天赋、命座全文 |
| `genshin_upgrade` | 加强体系（魔导角色 / 魔女的谕示） |
| `my_characters` / `my_teams` | 我的角色库 / 配队 |
| `ask_lumine` + `lumine_result` | 提交一次 AI 问答拿任务号，再取结果 |

问答做成异步是刻意的：MCP 的 `tools/call` 是同步调用，跑完一整轮对话会阻塞这条连接上的一切消息、也会撞客户端超时。所以毫秒级的查询类做成一个动作一个工具，长耗时的走「提交 → 取结果」。

## 界面形态

- **Web 界面**：浏览器打开即用，服务端驱动渲染——页面状态在服务端，断线重连后看到的是同一份状态。
- **Windows 桌面版**：原生窗口，游戏数据与存档随程序走，适合当单机工具用。
- **登录与帐号**：打开先登录；帐号切换不丢数据。

## 技术构成

| 层 | 用了生态里的什么 |
|---|---|
| Agent | [Atelier](/libs/atelier) Agent Harness：循环、工具、Skill、上下文压缩、信任闸门 |
| 工具协议 | [MCP](/libs/mcp)：把内核能力暴露给外部 AI 客户端 |
| 界面 | cjxt（Web，服务端驱动 UI）+ CangHui（仓颉原生 GUI，Windows 桌面） |
| 游戏数据 | genshin-db 预构建数据，随产品发布 |
| 存档 | 本地 JSON（角色库/配装/配队一份，会话各自一份） |

业务内核与界面是分开的：内核不依赖任何界面库，所以同一套业务逻辑能同时出现在浏览器和原生窗口里。

## 当前状态

- **可用**，日常形态是 Web + MCP 服务（同一个进程里既是界面也是 MCP 服务端）。
- **Windows 桌面版**并行维护，与 Web 版共用同一份业务内核。
- 已知限制：桌面版本地只能预览 PNG 附件（JPEG 显示「暂不支持预览」，但模型照样收到原图）；会话里的附图会随每轮请求重发（为了让它「记得」看过图）。
- **闭源**：产品不对外发布源码，本站仅作生态展示。
