# 星痕的炼金工房

> Atelier Starline · 人机共享的常驻桌面
>
> **暂未开源** · 本站仅作生态展示，源码未公开。

一块常驻的桌面：一组浮动窗口摆在屏上，人与 LLM 看**同一块屏**、改**同一份数据**。它要回答的问题是——Agent 长期在线时，除了聊天框还能长成什么样。

> **状态：正在重构。** 形态已定案（2026-11）：单体 `atelier` + `liveboard` 构架，不走「重构到插件宿主」那条路。界面已从 Svelte / 手写 WebSocket 迁到 cjxt，配置已从 `settings.json` 迁到配置库；剩下的是清掉遗留、把构架层收成能独立提取的形态。

## 它是什么

| 概念 | 对应 |
|---|---|
| 工具区 = 一台电脑 | 工具注册表与执行器是这台电脑的能力，`ToolContext` 是运行环境 |
| LLM = 用这台电脑的人 | 它通过敲命令（调工具）干活 |
| 面板 = 数据库 | `render()` 是查询视图，工具是写命令，存储引擎由面板自决 |
| 对话 = 一块 IM 面板 | 与其它面板平权（固定大小消息队列），不是上下文的主角 |
| 桌面 = 窗口系统 | 面板以浮动窗口摆放，可拖动 / 缩放 / 最小化 / 叠放 |
| Router + 多 Worker | Router 常驻协调、记忆、投递；Worker 上下文隔离、干活、只汇报结论 |

「切换项目」不是开新会话，是**改注意力**（换焦点目录），所以它的上下文组织方式与聊天应用根本不同。

## 为什么不是聊天框

聊天应用里，上下文就是对话历史，越用越长，最后只能裁掉旧的。星痕的做法是：

- **面板摘要化**：上下文里只放每个面板的一行摘要（名字 + 当前状态），细节由模型调面板工具去取。每轮为用不到的面板内容付 token，是原设计最贵的一处。
- **分层时间记忆**：所有时序记录（对话 / 工具调用 / 用户操作 / 系统日志 / 机器指标）做「分季财报式」物化快照——10 分钟 → 半小时 → 小时 → 天 / 周 / 月，越久越粗，不删下层；需要细节时沿层下钻。
- **技能渐进披露**：上下文只带技能目录（名字 + 一句话），完整指令由模型按需加载。

这三条合起来，长跑会话不靠裁历史省 token，而是让历史自己变小。

## 形态定案：单体 + 分层

2026-11 定案：一个进程、两层构架，不拆进程、不做插件宿主。

| 层 | 是什么 | 提供什么 |
|---|---|---|
| `atelier` | Agent 内核（生态里的框架层） | Agent 循环、Provider、Tool、Skill、事件总线、上下文压缩 |
| `liveboard` | 看板构架（本产品的构架层） | Panel / 面板工具 / 注意力 / 分层时间记忆 / Router·Worker |

此前计划的「重构到插件化宿主」作废，判据是收益与成本对不上：

| 插件化能给的 | 本产品的实际情况 |
|---|---|
| 进程隔离 / 热卸载 / 多租户 | 单用户、单机、单进程的常驻助手，一条都用不上 |
| 跨进程协议 seam | 却要付跨进程通信的代价（日志不可见、时序问题、产物缓存） |

单体之后，**分层就是唯一的边界**：构架层不依赖任何内部包（将来要单独提取），每个面板只依赖构架层且面板之间不互相引用，业务与 UI 不认识具体面板，装配层可以依赖全部。层乱了的代价不是编译不过，而是以后没法再把构架层提出来。

## 界面

- **桌面**：窗口拖动 / 缩放 / 最小化 / 关闭 / 叠放；顶栏菜单放全部面板（日常 / 记录 / 角色三组），任务栏只放已打开的窗口。窗口位置与尺寸存在浏览器本地，开关状态存在服务端——布局是每个浏览器自己的事，可见性是人与 AI 共享的。
- **手机**：同一入口按设备切成一列 IM 对话，与桌面看到同一份数据。
- **首次引导**：配置里还没有任何模型厂商时，桌面最上层盖一块引导页——填端点 → 真的测一次连接 → 才放行。每步有结果才前进，失败停在原地给原因。
- **系统设置**：左侧导航、右侧内容；三层嵌套是「厂商 → 模型 → 模型详情」，另有 MCP 服务、场景、系统提示词。改完热生效，不用重启。
- **场景**：一组「厂商 / 模型 / 思考档位 / 提示词」的命名快照，套用即写入那份唯一的当前选择。

## 开箱面板

桌面由 11 个窗口组成（10 个面板 + 系统设置）：

| 面板 | 干什么 |
|---|---|
| 聚焦 | 当前注意力：聚焦的目录 / 文件 / 视口 |
| 待办 | 任务清单 |
| 对话 | 与 LLM 对话（消息队列 + 模型胶囊 + 推理档位） |
| 用户操作 | 界面上点了什么 |
| Agent 活动 | 工具调用记录 |
| 系统日志 | 服务自身日志，可往前翻页 |
| 系统状态 | 机器指标 |
| 角色 | 角色卡：档案 + 人设，注入上下文 |
| 关系 | 好感 / 信任 / 默契，随互动演变 |
| 用户画像 | 偏好 + 隐私分级 |
| 系统设置 | 厂商 / 模型 / 模型详情 / MCP / 系统提示词 |

面板是自包含模块：一处注册 = 挂载 + 操作（LLM 工具与界面动作双入口）+ 注册技能。加一个面板就是加一个模块。

## 技术构成

| 层 | 用了生态里的什么 |
|---|---|
| Agent 内核 | [Atelier](/libs/atelier)：循环、工具、Skill、事件流、上下文压缩 |
| 构架层 | `liveboard`：面板机制、注意力、分层时间记忆、Router·Worker |
| 界面 | cjxt 服务端渲染（桌面 + 手机同一份页面代码） |
| 配置 | bstorm 文档库：厂商 / 模型 / 档位 / MCP / 当前选择 |
| 历史 | tsdb 时序库：五类序列 + 物化桶链 |
| 外部渠道 | QQ 与 MCP 两条入口，同一套「准入 → 处理 → 投递」链路 |

数据全部在本地。同一份数据目录只允许开一个实例（启动时抢带心跳的锁，抢不到就打印占用者并退出），避免两个进程互相覆盖写。
